# Video upload and analysis progress

The review dialog separates transfer from processing. Upload uses the existing private binary endpoint through XMLHttpRequest so Safari and Chrome can report actual bytes sent. The percent describes transfer only. At 100%, the screen waits for the server's successful save response before saying the video is saved and allowing background processing. It shows upload speed estimates only after a measurable transfer interval, and withdraws them if transfer stalls. Cancel and retries keep the existing idempotent upload ID. The same account header, capability headers, same-origin cookies and session-invalid handling apply as for private fetches.

Analysis shows preparation, tracking, coaching and (when enabled) body/form-guide preparation. A nullable progress column records the run's queue time, first start, current phase, update and completion, optional body processing and attempt count. All writes use the existing worker lease fence. GPU queue yields preserve the first start and active phase. Explicit retry/reanalysis starts a new timing record. Existing reviews remain compatible; missing timestamps are not invented from the original upload date.

Processing estimates use 3–10 completed, comparable reviews already returned by the account's owner-scoped list. They match body mode, upload mode, similar duration (within a factor of two) and attempt count. The displayed range uses the observed interquartile duration with headroom, less current elapsed processing time. Failed/untimed runs and the current review are excluded. A queue has no promised start time. With insufficient history the UI explicitly says no estimate is available; an overrun becomes “Taking longer than recent reviews”, never a perpetual zero-second countdown. These are planning estimates, not a guaranteed deadline or a measure of completed computation. Timing collection begins with this release; older reviews do not supply measured completion times.

Polling remains every five seconds, with bounded requests, immediate rechecks on return/connection restoration, and automatic detail retries. Delayed updates show reconnection rather than pretending to know current progress. The selected review opens automatically after upload. A shortcut surfaces an active analysis when returning to the upload screen. A saved review can continue while the user navigates elsewhere; an unfinished transfer needs the current window open. Completion is visible on returning to the review; this does not add push notifications.

Verification uses synthetic files/accounts only: measured-byte progress, delayed save acknowledgement, navigation, queue/body continuation, elapsed time, insufficient/comparable timings, overruns, reconnection, keyboard/accessibility/mobile layout, replay regression and private access. Database coverage checks owner isolation, retry resets and persisted start times across GPU resumes. No paid model or GPU evaluations are required for this change.
