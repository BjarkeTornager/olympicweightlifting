# Automatic meal categories

Coach chooses breakfast, lunch, dinner or snack when preparing food. It must not ask the user to select that category. The order of evidence is the stated meal/eating time, ongoing meal context and known routine, then relevant local time together with the foods and portion. Morning oats, Yakult and coffee can be breakfast; a small drink between meals can be a snack. Time windows are clues: an explicit late breakfast, dinner report or night-shift routine takes priority. An uncertain category remains an editable assumption in the review notes. Existing saved meal categories are preserved unless a correction is requested.

The engine previously supplied the local date without a local clock time. It now provides the request time and renders earlier message timestamps in the athlete's timezone. Attached photos, retrieved photos and catalog results include local upload timing. A photo's editable library date remains separate from its upload timestamp. When these local dates differ, the photo has no meal-time hint. Upload time is always a weak clue rather than a confirmed eating or capture time, so an old dinner photo uploaded at breakfast must not acquire the current meal category just from that upload.

No schema migration or bulk retagging occurs. Meal review/save behavior, food-versus-health image classification, photo ownership checks and ingredient evidence rules remain in place. Conversation style and provider configuration are unchanged.

The deliberately refreshed fixed-policy baseline is covered by deterministic tests: date rollover, fractional timezone offsets, daylight-saving changes, backdated-photo timing, and the actual engine receiving original morning photo context during an evening request. The integration case verifies inspection, a linked review, explicit save and later corrections that retain the confirmed meal category. These checks use synthetic data and scripted model replies; they verify context delivery and supported actions, not real-provider classification accuracy. No new GEPA or real-provider quality evaluation was performed.
